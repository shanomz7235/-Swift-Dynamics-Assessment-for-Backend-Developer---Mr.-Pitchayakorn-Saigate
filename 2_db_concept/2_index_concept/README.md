# Database Indexing: ข้อดีและข้อจำกัด

## Index คืออะไร

Index คือโครงสร้างข้อมูลเสริมที่ฐานข้อมูลสร้างขึ้นมา เพื่อให้ค้นหาข้อมูลได้เร็วขึ้น โดยไม่ต้องไล่อ่านทุกแถวในตาราง

เปรียบเหมือน **สารบัญท้ายหนังสือ** ถ้าไม่มีสารบัญ ต้องเปิดไล่ทีละหน้าเพื่อหาคำที่ต้องการ (เรียกว่า full table scan) แต่ถ้ามีสารบัญ ก็เปิดไปหน้าที่ต้องการได้เลย

ตัวอย่าง:

```sql
CREATE INDEX idx_employee_email ON employees (email);
```

หลังจากนี้ query ที่ค้นหาด้วย `email` จะเร็วขึ้นมาก

## ข้อดี
1. ค้นหาข้อมูลเร็วขึ้น ลดจากการไล่อ่านทั้งตาราง (ช้าลงตามจำนวนแถว) เหลือการค้นผ่านโครงสร้างที่จัดไว้แล้ว (ส่วนใหญ่เป็น B-Tree)

2. เร่ง JOIN คอลัมน์ที่ใช้ JOIN (เช่น foreign key) ถ้ามี index จะจับคู่ข้อมูลระหว่างตารางได้เร็วขึ้น

3. เร่ง ORDER BY และ GROUP BY Index เก็บข้อมูลเรียงลำดับไว้แล้ว ฐานข้อมูลจึงไม่ต้องเสียเวลาเรียงใหม่ทุกครั้ง

4. ช่วยบังคับความไม่ซ้ำ Unique index ช่วยรับประกันว่าค่าในคอลัมน์ไม่ซ้ำ เช่น email หรือรหัสพนักงาน

5. ลดภาระของเซิร์ฟเวอร์ อ่านข้อมูลน้อยลง ใช้ CPU และ disk I/O น้อยลง รองรับผู้ใช้พร้อมกันได้มากขึ้น

## ข้อจำกัด

1. เขียนข้อมูลช้าลง ทุกครั้งที่ INSERT, UPDATE, DELETE ฐานข้อมูลต้องอัปเดต index ด้วย ยิ่งมี index มาก การเขียนยิ่งช้า

2. กินพื้นที่เพิ่ม Index เป็นข้อมูลอีกชุดที่ต้องเก็บ บางครั้งขนาดรวมของ index ใหญ่ใกล้เคียงหรือมากกว่าตารางเอง

3. ไม่ได้ช่วยทุก query Index จะไม่ถูกใช้ หรือใช้ไม่ได้ผล ในกรณีเช่น
- ใช้ฟังก์ชันครอบคอลัมน์ เช่น `WHERE YEAR(created_at) = 2026`
- ใช้ `LIKE '%abc'` (wildcard นำหน้า)
- เปรียบเทียบคนละชนิดข้อมูล เช่น คอลัมน์เป็น string แต่ส่งค่าเป็นตัวเลข
- ตารางเล็กมาก ซึ่งอ่านทั้งตารางเร็วกว่าอยู่แล้ว

4. คอลัมน์ที่ค่าซ้ำมาก (low cardinality) ได้ประโยชน์น้อย เช่น คอลัมน์เพศ หรือ status ที่มีไม่กี่ค่า index แยกแยะข้อมูลได้ไม่ดี ฐานข้อมูลอาจเลือกไม่ใช้ index เลย

5. ต้องดูแลรักษา Index อาจเกิด fragmentation เมื่อมีการแก้ไขข้อมูลบ่อย ต้อง rebuild หรือ reorganize เป็นระยะ

6. ลำดับคอลัมน์ใน composite index สำคัญ Index แบบหลายคอลัมน์ เช่น `(last_name, first_name)` ใช้ได้กับ query ที่ค้นด้วย `last_name` หรือทั้งสองคอลัมน์ แต่ใช้ไม่ได้ผลกับ query ที่ค้นด้วย `first_name` อย่างเดียว

## หลักการเลือกสร้าง Index

**ควรสร้างเมื่อ**
- คอลัมน์ที่ใช้ใน `WHERE` บ่อย
- คอลัมน์ที่ใช้ `JOIN` (foreign key)
- คอลัมน์ที่ใช้ `ORDER BY` หรือ `GROUP BY` บ่อย
- ตารางใหญ่ และอ่านมากกว่าเขียน

**ไม่ควรสร้างเมื่อ**
- ตารางเล็ก
- ตารางที่เขียนบ่อยมากแต่อ่านน้อย
- คอลัมน์ที่ไม่เคยถูกใช้ค้นหา
- คอลัมน์ที่ค่าซ้ำมาก
